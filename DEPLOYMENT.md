# GitHub Pages deployment

This site now builds as a static Vite + React app. app/main.tsx renders the existing app/page.tsx unchanged. Scene and UI logic remain in their existing files.
The previous Vinext/Cloudflare config is preserved in vite.server.config.ts for reference; it is not used by npm run build. No server is needed by Pages.

## Local work

- npm ci (Node 22.13+; Actions uses Node 22)
- npm run dev (localhost:3000; use the URL printed by Vite)
- npm run build (static dist/index.html and dist/assets)
- npm run preview (HTTP preview of the production build)
- node scripts/export-html.mjs still updates the separate offline HTML; Pages uses the React build, not that file.

## Base path

vite.config.ts defaults to './' for portable local builds.
In GitHub Actions, GITHUB_REPOSITORY supplies the actual owner/repository; base becomes '/actual-repository/' automatically. An owner.github.io repository uses '/'. No username or repository has been guessed.
For a manual explicit build, set PAGES_BASE_PATH to '/REPOSITORY-NAME/' and replace REPOSITORY-NAME with your real repository name. Do not include the username in this path.
Example PowerShell: $env:PAGES_BASE_PATH='/REPOSITORY-NAME/'; npm run build
Remove-Item Env:PAGES_BASE_PATH clears the override afterwards.

## First deployment

1. Create your GitHub repository. For easiest first setup create it empty, without a generated README. Choose your own name.
2. Review and commit project source and package-lock.json, then push a branch named main. The local repository currently has no commits or remote and its unborn branch is master; prepare main during your first commit/push. Never force-push or delete an existing remote.
3. In Settings > Pages, set Build and deployment > Source to GitHub Actions.
4. Push to main or run Actions > Deploy GitHub Pages > Run workflow. If the first run happened before Pages was enabled, rerun it.
5. Open the URL shown by the deployment job. Repository availability depends on your GitHub plan and repository visibility.

Workflow .github/workflows/deploy.yml runs npm ci, npm run build, uploads only ./dist and deploys it with the built-in GITHUB_TOKEN / OIDC permissions. No personal access token is required in source.

## Later updates

Continue editing this same Codex project. Build and review, commit the source changes, then push main. Actions rebuilds and updates the site. Do not upload node_modules or dist yourself.

## Resource and security audit

- Scene models and textures are generated by Three.js/code, not external GLB or texture URLs.
- Active CSS embeds font data. Auxiliary public font CSS now points to the bundled TTF files with relative URLs; font license files remain included.
- Pixel SVGs are inline; audio uses Web Audio API.
- Source entry /app/main.tsx is a Vite build entry, rewritten to base-prefixed hashed assets during build.
- .gitignore excludes node_modules, dist, .env*, .DS_Store, local backups and compiler caches; required source/public assets remain included.
- A pattern scan found no .env files or recognizable API keys, access tokens, private keys or credential assignments. This is not a guarantee against all possible secrets. Never add credentials to public assets or VITE_* variables (those are public browser code).
- Existing .openai/hosting.json contains null D1/R2 bindings, not credentials.
- In-progress discovery and audio settings are browser localStorage; the hosted origin has separate preferences from the offline file.
